## 1. Disclaimer

**Displayed on every analysis result and on the homepage.**

> **AI-Generated Content Notice**
>
> The counter-perspectives presented by EchoBreaker are generated by a large language model (LLM) and do **not** represent verified facts, professional advice, or editorial opinions. They are computationally produced alternative viewpoints intended to encourage critical thinking.
>
> - **Not a substitute for expert judgment.** In domains such as healthcare, public policy, or national security, always consult qualified professionals before acting on any information.
> - **May contain inaccuracies.** LLMs can hallucinate references, misrepresent nuance, or produce arguments that sound plausible but are factually wrong.
> - **No endorsement implied.** Presenting a counter-argument does not mean EchoBreaker endorses that position. The tool surfaces *possible* opposing viewpoints — not *correct* ones.
> - **No user data is stored.** YouTube captions are processed in real-time and discarded immediately after analysis. No personal data, viewing history, or analysis results are persisted.

## 2. Model Card

### 2.1 Model Identity

| Field | Value |
|---|---|
| **Model** | Azure OpenAI GPT-5.4 Mini (cloud) / Llama 3 8B via Ollama (local fallback) |
| **Provider** | Configurable: `PROVIDER=azure` or `PROVIDER=local` |
| **Quantization** | Cloud: none (full-precision API) · Local: Ollama default (Q4_K_M for Llama 3) |
| **Context window** | Transcript truncated to 20,000 characters |
| **Temperature** | 0.7 (analysis) · 0.3 (verification) |
| **Output format** | Structured JSON with schema validation (Pydantic v2) |

### 2.2 Intended Use

| | Description |
|---|---|
| **Primary** | Educational tool for media literacy — helps users discover counter-perspectives to YouTube video content |
| **Secondary** | Portfolio demonstration of Responsible AI engineering, MLOps pipeline design, and provider-abstraction patterns |
| **Users** | General public, researchers, educators, journalists, media literacy advocates |

### 2.3 Out-of-Scope Use

This tool is **NOT designed or validated** for:

- **Clinical decision-making** — Must not be used to generate medical counter-opinions or challenge clinical guidelines
- **Legal or regulatory analysis** — Output does not constitute legal advice or regulatory assessment
- **Intelligence analysis** — Not validated for defence, security, or geopolitical threat assessment
- **Content moderation** — Not a classifier; cannot determine whether content is harmful, misleading, or illegal
- **Automated decision systems** — Must not be integrated into systems that make consequential decisions about individuals

### 2.4 Known Limitations

| Limitation | Impact | Mitigation |
|---|---|---|
| **Hallucinated references** | Academic references (author, title, year) may be fabricated by the LLM | Scholar search URLs allow users to verify independently |
| **Western-centric bias** | Training data skews toward English-language, Western perspectives | Explicitly noted in UI; future work to support multilingual analysis |
| **Transcript quality** | YouTube auto-captions contain errors, especially for accented speech or technical jargon | Errors propagate to analysis; users should review source video |
| **Recency cutoff** | LLM training data has a knowledge cutoff and may miss recent developments | Timestamp displayed; users advised to check current sources |
| **Oversimplification** | Complex topics compressed into 2-sentence counter-arguments may lose nuance | "Why It Matters" field and Scholar links provide deeper context |
| **No content filtering** | Tool will attempt analysis on any YouTube video, including harmful content | Future: integrate content safety classification layer |

### 2.5 Evaluation

| Metric | Method | Status |
|---|---|---|
| **Factual accuracy** | Manual review of 50 randomly sampled analyses | Planned |
| **Argument quality** | Expert rating (1-5 scale) by domain specialists | Planned |
| **Bias detection** | Systematic testing across politically sensitive topics | Planned |
| **Latency** | Automated: caption extraction + LLM inference | ~5 seconds (Azure) |

## 3. Ethical Guidelines

EchoBreaker adheres to the following principles, informed by the EU AI Act, IEEE Ethically Aligned Design, and Microsoft Responsible AI Standard.

### Principle 1: Epistemic Humility
> *We do not tell users what to think. We show them what else to think about.*

Counter-perspectives are framed as possibilities, not corrections. Language avoids authoritative claims like "this is wrong" and instead uses "another perspective suggests..."

### Principle 2: Transparency
- The LLM model, provider, and version are disclosed in the health endpoint and UI footer.
- Every analysis includes a Responsible AI disclaimer.
- No hidden processing — the full pipeline (caption extraction → LLM analysis) is documented and open-source.

### Principle 3: Privacy by Design
- **No audio/video download** — only text captions are extracted.
- **No data persistence** — captions and results are processed in-memory and discarded.
- **No user tracking** — no cookies, analytics, or telemetry.
- **No third-party data sharing** — API calls go only to the configured LLM provider.

### Principle 4: Fairness and Non-Discrimination
- Counter-arguments are generated across three balanced dimensions (Ethical, Empirical, Logical) to avoid systematically favoring one mode of reasoning.
- The system does not target specific political, religious, or cultural positions.
- Recognized limitation: underlying LLM training data contains societal biases that may surface in outputs.

### Principle 5: Human Agency
- EchoBreaker is a *complementary* tool, not a replacement for human judgment.
- Users maintain full control: results are presented for consideration, not action.
- "Explore Sources" is opt-in — users choose whether to see additional content.

### Principle 6: Accountability
- All code is open-source and auditable.
- Model Card and Risk Assessment are maintained and versioned.
- Feedback mechanism enables users to report problematic outputs.

## 4. Risk Assessment

### 4.1 Risk Matrix

| Risk | Severity | Likelihood | Mitigation |
|---|---|---|---|
| **Hallucinated academic references** | Medium | High | Scholar links enable verification; disclaimer warns users |
| **Legitimizing harmful positions** | High | Medium | Future: content safety pre-screening; guardrails for sensitive topics (e.g., Holocaust denial, vaccine safety) |
| **Reinforcing false balance** | Medium | Medium | Not all viewpoints deserve "equal time" — future: confidence-weighted presentation |
| **Misuse for propaganda** | High | Low | Tool generates counter-arguments, not persuasive content; open-source audit trail |
| **Privacy violation via transcript analysis** | Medium | Low | No data stored; no user accounts; GDPR-compliant by design |
| **Algorithmic bias amplification** | Medium | Medium | Three-dimensional framework reduces single-axis bias; bias testing planned |
| **Misinformation laundering** | High | Medium | Counter-arguments to conspiracy videos could unintentionally validate them; future: topic sensitivity classification |

### 4.2 Sensitive Topic Categories

The following topics require additional guardrails (planned for future versions):

| Category | Risk | Planned Mitigation |
|---|---|---|
| Medical claims (vaccines, treatments) | Counter-arguments could endanger health | Flag + defer to WHO/EMA guidelines |
| Historical atrocities (Holocaust, genocides) | "Counter-perspective" framing is inappropriate | Refuse analysis; display educational redirect |
| Active military/security operations | Could surface operationally sensitive viewpoints | Content classification + blocking |
| Self-harm, suicide, eating disorders | Counter-arguments could normalize harmful behavior | Content safety API integration |

### 4.3 Deployment Considerations

| Environment | Assessment |
|---|---|
| **Personal/educational use** | Low risk — intended use case |
| **Newsroom/journalism** | Medium risk — requires editorial oversight |
| **Healthcare settings** | High risk — NOT validated; out-of-scope use |
| **Defence/intelligence** | High risk — NOT validated; out-of-scope use |
| **Public deployment (web)** | Medium risk — requires content safety layer and rate limiting |

## 5. Feedback Mechanism

### 5.1 User-Facing Component

Every analysis result includes a feedback section with three options:

1. **Flag Inaccuracy** — "This counter-argument contains factual errors"
2. **Flag Harmful Content** — "This output could cause harm or is inappropriate"
3. **Flag Bias** — "This output shows systematic bias toward a particular viewpoint"

### 5.2 Feedback Data Structure

```json
{
  "timestamp": "2026-04-05T14:30:00Z",
  "video_url": "https://youtube.com/watch?v=...",
  "counter_argument_type": "Ethical",
  "flag_type": "inaccuracy | harmful | bias",
  "user_comment": "Optional free-text explanation",
  "counter_argument_content": "The flagged content"
}
```

### 5.3 Feedback Handling Policy

- Feedback is stored locally (no cloud transmission) in a structured log.
- Flagged outputs are reviewed in batches to identify systematic issues.
- Recurring patterns inform prompt engineering improvements and guardrail updates.
- No user-identifying information is collected with feedback.
